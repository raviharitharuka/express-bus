Express buses despite a driver shortage

Nuremberg has spare buses but not enough drivers. ExpressBus finds the idle time hidden inside existing driver duties and checks, with an optimization model, whether new express routes can run on that time instead of on new hires.

GET /idle-drivers

Idle-time detection

For every driver: driving hours, each idle gap of 60 minutes or more with where they wait, and free capacity up to their maximum shift.

POST /optimize

Express route optimization

A CP-SAT model assigns express round trips to idle time (or allowed overtime), counts the new drivers otherwise needed, and recommends routes that fit together.

POST /emergency

Breakdown recovery

Takes the broken bus out of the pool, finds the nearest station with a spare bus and the nearest free driver, and returns an ETA with a timeline.

GET /dashboard

Operations dashboard

Utilization, idle drivers, spare buses per station, driver shortages from the vacation calendar, a launch recommendation and rebalancing hints.

POST /lotse

Lotse, the dispatch assistant

Ask in plain language. Keyword rules route the question to a service; with an API key, Claude classifies it and phrases the answer from the service's data only.

/admin

What-if editing

Mark a driver sick, add vacation days or break a bus; every engine reflects it. Re-run the optimization for a before/after view, then reset.

Who it's for

People who keep buses running

A prototype built for a hackathon. It shows what these roles could get from planning data they already have.

Service planners

Decide whether a new express line can launch with the drivers on the roster, and what it would cost in overtime or hires.

Dispatchers

React to a breakdown or a sick driver in minutes: which spare bus, which free driver, how long until service resumes.

Operations managers

See utilization, spare capacity and upcoming shortages at a glance, and ask Lotse instead of digging through spreadsheets.

Inside the optimizer

  1. Trips become tasks. Each express departure is a round trip: out, turnaround, back to the start station.
  2. Tasks meet drivers. A driver can take a task only while waiting at its start station, in a gap long enough to finish before their next trip.
  3. Rules hold. No overlaps, duty within the maximum shift, at most 4.5 h driving per 5 h, no vacation days, overtime only if allowed, enough spare buses.
  4. Priorities decide. Cover as many trips as possible, then use the fewest new drivers, then the least overtime.

Built to demo reliably

  • One shared 8-second solve budget; a timeout returns the last good result marked cached.
  • scripts/validate_solution.py re-checks every assignment against the rules, independently of the solver.
  • 116 automated tests, including checks that the API matches its written contract.
  • The frontend falls back to mock data when the backend is unreachable.
  • Lotse falls back to keyword rules when Claude is unavailable or slow (5 s timeout).

Data

What is real and what is synthetic

GTFS timetables say when buses run, not who drives them. In GTFS mode the real trips are chained into invented duties so the engines have rosters to work with. Every response says which parts are real.

Synthetic mode uses a hand-made network: 5 stations, 20 drivers, 50 buses and a 30-day calendar.

Limitations

An honest prototype

Simplified, not compliant

  • The break and shift rules are simplified for the demo; they do not claim compliance with EU 561/2006, German working-time law or collective agreements.
  • No empty repositioning trips and no handover buffer between trips.
  • No daily or weekly driving caps, rest periods between days, or qualifications.

Not built yet

  • Machine-learning forecasts; today's shortage alerts come from the vacation calendar.
  • GTFS-Realtime, real rosters, passenger or ticketing data.
  • A database, authentication and real maps (the map is a schematic).

Run it

One command

Needs Python 3.10+ and Node.js 20.9+. Starts the backend on port 8000 and the dashboard on port 3000, with a demo clock that has drivers on shift.

git clone https://github.com/raviharitharuka/express-bus.git
cd express-bus
./run_demo.sh                    # or run_demo.bat on Windows
DATA_SOURCE=gtfs ./run_demo.sh   # real VAG trips, synthetic roster

Open http://localhost:3000 for the dashboard and http://localhost:8000/docs for the API. Full details in the repository README.

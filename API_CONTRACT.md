# API Contract

Shared contract between the FastAPI backend (`backend/`) and the Next.js frontend (`frontend/`).

- **Base URL (dev):** `http://localhost:8000` (interactive docs at `/docs`)
- **Format:** JSON, `Content-Type: application/json`
- **Field naming:** `camelCase`
- **Times:** `"HH:MM"` (24h, local). **Dates:** `"YYYY-MM-DD"`. **Percentages:** numbers `0–100`, one decimal.
- **Mocks:** every endpoint has a matching file in `frontend/public/mock/`, served by Next.js at `/mock/<name>.json`. The mocks are real backend output (`DEMO_DATE=2026-10-05`, `DEMO_TIME=09:15`), so mock and live mode show the same numbers.

## MVP data scale

| Entity   | Values                                                                 |
|----------|------------------------------------------------------------------------|
| Stations | `Central Station`, `Airport`, `North Station`, `South Station`, `University` |
| Drivers  | `D001` – `D020`                                                        |
| Buses    | `B001` – `B050`                                                        |
| Routes   | Regular `R1` – `R10`; candidate express routes `E1` – `E5`             |
| Calendar | 30 days, `2026-10-01` – `2026-10-30`; other dates use the weekday/weekend rules without the calendar |

Data lives in `backend/data/` and is generated by `backend/scripts/generate_data.py`.

## Errors (all endpoints)

```json
{ "error": "BUS_NOT_FOUND", "message": "Bus B099 does not exist" }
```

| HTTP  | `error` values                                                   |
|-------|------------------------------------------------------------------|
| `400` | `INVALID_REQUEST`, `INVALID_DATE`, `INVALID_TIME`                |
| `404` | `BUS_NOT_FOUND`, `DRIVER_NOT_FOUND`, `STATION_NOT_FOUND`         |
| `501` | `NOT_IMPLEMENTED` (`ROAD_CLOSURE` incidents)                     |

## 1. `GET /idle-drivers`

Idle-time profile of every driver working on a given day: driving time, idle gaps (split-shift breaks and long terminal layovers) and spare capacity within their max shift.

**Query params**

| Param  | Type   | Required | Default  |
|--------|--------|----------|----------|
| `date` | string | no       | tomorrow |

**Response `200`** — mock: `idle-drivers.json`

```json
{
  "date": "2026-10-06",
  "totalDrivers": 20,
  "workingDrivers": 20,
  "idleDriverCount": 10,
  "totalIdleHours": 32.5,
  "totalFreeCapacityHours": 73.0,
  "drivers": [
    {
      "driverId": "D003",
      "homeStation": "Central Station",
      "dutyStart": "07:00",
      "dutyEnd": "16:10",
      "drivingHours": 4.7,
      "idleHours": 4.0,
      "freeCapacityHours": 4.8,
      "idleWindows": [
        { "start": "07:35", "end": "08:35", "station": "South Station" },
        { "start": "09:55", "end": "10:55", "station": "South Station" }
      ],
      "recommendedRoute": "E5"
    }
  ]
}
```

| Field                          | Type           | Notes                                                    |
|--------------------------------|----------------|----------------------------------------------------------|
| `workingDrivers`               | integer        | Drivers with a duty that day (not on vacation, duty runs that day type) |
| `idleDriverCount`              | integer        | Working drivers with at least one idle window            |
| `drivers[]`                    | array          | One entry per working driver, sorted by `driverId`       |
| `drivers[].drivingHours`       | number         | Sum of trip durations                                    |
| `drivers[].idleHours`          | number         | Sum of `idleWindows`                                     |
| `drivers[].freeCapacityHours`  | number         | `idleHours` + (`maxShiftHours` − duty span): idle gaps plus room to extend the duty |
| `drivers[].idleWindows`        | array          | Gaps ≥ 60 min between consecutive trips; empty if none   |
| `idleWindows[].station`        | string         | Where the driver is waiting (may be away from home)      |
| `drivers[].recommendedRoute`   | string \| null | First express route with a departure that fits one of the windows |

Sanity check from the command line: `python scripts/top_idle.py [YYYY-MM-DD]` (run in `backend/`) prints the 10 largest idle windows and every driver's driving, idle and free hours.

## 2. `POST /optimize`

Tries to staff each candidate express route's departures from idle windows (best fit, no double booking).

**Request** (body optional; defaults shown)

```json
{
  "date": "2026-10-06",
  "allowOvertime": false,
  "maxNewRoutes": 5
}
```

| Field           | Notes                                                                    |
|-----------------|--------------------------------------------------------------------------|
| `date`          | Defaults to tomorrow                                                     |
| `allowOvertime` | Also use time after a duty ends, up to `maxShiftHours`, for drivers with `overtimeAvailable` |
| `maxNewRoutes`  | 1–10; how many candidates to evaluate, in order                          |

**Response `200`** — mock: `optimize.json`

```json
{
  "date": "2026-10-06",
  "currentUtilization": 66.3,
  "optimizedUtilization": 71.7,
  "totalIdleHoursAvailable": 32.5,
  "totalIdleHoursUsed": 10.2,
  "newDriversRequired": 1,
  "recommendations": [
    {
      "route": "E1",
      "name": "Central Station - Airport Express",
      "idleHoursUsed": 2.5,
      "newDriversRequired": 0,
      "feasible": true,
      "assignedDrivers": ["D005"],
      "reason": "Covered by idle time of D005"
    },
    {
      "route": "E4",
      "name": "Airport - University Express",
      "idleHoursUsed": 3.0,
      "newDriversRequired": 1,
      "feasible": false,
      "assignedDrivers": ["D007", "D008"],
      "reason": "No spare bus at Airport; 1 of 4 departures unstaffed"
    }
  ]
}
```

| Field                                  | Type     | Notes                                                        |
|----------------------------------------|----------|--------------------------------------------------------------|
| `currentUtilization`                   | number   | Driver utilization % = driving time ÷ duty span              |
| `optimizedUtilization`                 | number   | Same, after adding the feasible express trips                |
| `totalIdleHoursUsed`                   | number   | Hours consumed by **feasible** routes only                   |
| `newDriversRequired`                   | integer  | Total across all recommendations                             |
| `recommendations[].idleHoursUsed`      | number   | Idle hours the route would consume (also shown for infeasible routes) |
| `recommendations[].newDriversRequired` | integer  | Extra drivers for the unstaffed departures (8 h shifts)      |
| `recommendations[].feasible`           | boolean  | All departures staffed **and** a spare bus at the origin station |
| `recommendations[].assignedDrivers`    | string[] | Drivers whose idle time covers the route                     |
| `recommendations[].reason`             | string   | One-line explanation for the UI                              |

## 3. `POST /emergency`

Reports an incident and returns the automatic recovery plan.

**Request**

```json
{
  "incidentType": "BREAKDOWN",
  "busId": "B021",
  "station": "Airport",
  "time": "09:15"
}
```

| Field          | Type   | Required             | Notes                                          |
|----------------|--------|----------------------|------------------------------------------------|
| `incidentType` | enum   | yes                  | `BREAKDOWN` \| `DRIVER_SICK` \| `ROAD_CLOSURE` (returns `501` for now) |
| `station`      | string | yes                  | Where the incident is; one of the 5 stations   |
| `busId`        | string | for `BREAKDOWN`      | `B001`–`B050`                                  |
| `driverId`     | string | for `DRIVER_SICK`    | `D001`–`D020`                                  |
| `time`         | string | no                   | Defaults to now                                |

**Response `200`** — mock: `emergency.json`

```json
{
  "incidentId": "INC-0001",
  "incidentType": "BREAKDOWN",
  "status": "DISPATCHED",
  "brokenBus": "B021",
  "replacementBus": "B027",
  "driver": "D011",
  "sourceStation": "North Station",
  "destinationStation": "Airport",
  "distanceKm": 4,
  "etaMinutes": 10,
  "timeline": [
    { "time": "09:15", "step": "Breakdown reported: B021 at Airport" },
    { "time": "09:15", "step": "Airport has 0 spare buses; nearest is North Station (5 spare, 4 km)" },
    { "time": "09:16", "step": "Idle driver D011 selected at North Station (free until 12:30)" },
    { "time": "09:17", "step": "D011 departs North Station with B027" },
    { "time": "09:25", "step": "B027 arrives at Airport; B021 sent to maintenance, inventory updated" }
  ]
}
```

| Field            | Type            | Notes                                                       |
|------------------|-----------------|-------------------------------------------------------------|
| `status`         | enum            | `DISPATCHED` \| `NO_RESOURCES`                              |
| `brokenBus`      | string \| null  | `null` for `DRIVER_SICK`                                    |
| `replacementBus` | string \| null  | For `DRIVER_SICK`, the sick driver's bus                    |
| `driver`, `sourceStation`, `distanceKm`, `etaMinutes` | nullable | `null` when `status` is `NO_RESOURCES` |
| `distanceKm`     | number          | Driver's total travel: to the spare bus, then to the incident |
| `etaMinutes`     | integer         | Minutes until the replacement is at the incident station    |
| `timeline`       | array           | 3–6 short steps, chronological                              |

## 4. `POST /copilot`

Natural-language Q&A for dispatchers. Rule-based: the question is matched to an engine (optimize, idle drivers, emergency, spare buses, shortages) and the result is phrased as text.

**Request**

```json
{ "question": "Can we launch a new express route tomorrow?" }
```

**Response `200`** — mock: `copilot.json`

```json
{
  "question": "Can we launch a new express route tomorrow?",
  "answer": "Yes. On 2026-10-06 4 express route(s) can launch with 0 new drivers: E1 (...), E2 (...), E3 (...), E5 (...). Driver utilization rises from 66.3% to 71.7%. Not feasible: E4 (No spare bus at Airport; 1 of 4 departures unstaffed).",
  "confidence": 90,
  "followUps": [
    "Which drivers have unused capacity today?",
    "What happens if Bus B021 breaks down now?",
    "Which station will run out of buses tonight?"
  ]
}
```

| Field        | Type     | Notes                                       |
|--------------|----------|---------------------------------------------|
| `confidence` | integer  | 0–100; 40 when the question isn't understood |
| `followUps`  | string[] | Suggested next questions (up to 3)           |

## 5. `GET /dashboard`

Everything the KPI dashboard needs in one call.

**Query params:** `date` (optional, default today)

**Response `200`** — mock: `dashboard.json`

```json
{
  "date": "2026-10-05",
  "kpis": {
    "driverUtilization": 66.3,
    "fleetUtilization": 40.0,
    "availableDrivers": 10,
    "availableBuses": 26,
    "predictedShortages": 3,
    "additionalRoutesIdentified": 4
  },
  "stations": [
    { "name": "Central Station", "totalBuses": 16, "availableBuses": 9, "maintenanceBuses": 1, "driversOnDuty": 6 }
  ],
  "recommendation": {
    "title": "Launch Express Route E3",
    "reason": "3.0 idle driver hours on North Station - South Station Express (D011)",
    "confidence": 92
  },
  "alerts": [
    { "level": "warning", "message": "Airport has 0 spare buses" },
    { "level": "critical", "message": "3 driver(s) short predicted on 2026-10-22" }
  ]
}
```

| Field                              | Type    | Notes                                                       |
|------------------------------------|---------|-------------------------------------------------------------|
| `kpis.fleetUtilization`            | number  | Buses assigned to today's duties ÷ 50                       |
| `kpis.availableDrivers`            | integer | Drivers with at least one idle window today                 |
| `kpis.availableBuses`              | integer | Spare buses across all stations                             |
| `kpis.predictedShortages`          | integer | Drivers missing on the worst upcoming calendar day (vacations) |
| `kpis.additionalRoutesIdentified`  | integer | Feasible express routes from `/optimize` for this date      |
| `stations[]`                       | array   | Always 5 entries; `totalBuses` sums to 50                   |
| `stations[].availableBuses`        | integer | Spare buses ready to dispatch                               |
| `stations[].driversOnDuty`         | integer | Working drivers based at this station today                 |
| `alerts[].level`                   | enum    | `info` \| `warning` \| `critical`                           |

## Demo story (how the numbers fit together)

- 50 buses but only 20 drivers: 20 buses on duty, 26 spare, 4 in maintenance → fleet utilization 40%.
- The weekday timetable has split shifts (D002, D005, D007, D011, D015, D018), long layovers (D003, D008, D013, D017) and short duties (D004, D010, D014, D019) → driver utilization 66.3%, 32.5 idle hours.
- The optimizer staffs E1, E2, E3 and E5 from that idle time with 0 new drivers (66.3% → 71.7%). E4 fails: Airport has no spare bus and one departure has no free driver.
- Airport has 0 spare buses, so a B021 breakdown there is covered from North Station by idle driver D011 in 10 minutes.
- Vacations on 2026-10-22/23 leave 3 duties uncovered → the dashboard's critical shortage alert.
